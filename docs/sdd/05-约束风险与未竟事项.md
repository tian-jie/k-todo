# 05 约束、风险与未竟事项

## 5.1 关键约束
- Kindle 浏览器能力弱，必须 ES5 兼容
- E-ink 刷新慢，不适合复杂动画
- 设备输入能力有限，登录交互需尽量简化

## 5.2 主要风险
- 风险 R1：旧浏览器兼容问题导致 UI 异常
  - 应对：禁用现代语法与复杂布局，真机测试
- 风险 R2：网络波动导致轮询失败
  - 应对：本地缓存 + 重试策略 + 超时机制
- 风险 R3：done 接口重复提交
  - 应对：后端幂等更新
- 风险 R4：Phase 3 登录体验差
  - 应对：后续评估“短密码 + 长会话”或设备绑定码

## 5.3 未竟事项（建议纳入后续需求池）
- U1：任务新增/编辑入口（Kindle 端或 Web 管理端）
- U2：任务排序策略（截止时间、优先级、手动排序）
- U3：冲突策略（多端并发更新）
- U4：离线 done 的延迟同步队列
- U5：时区策略（服务器 UTC、前端本地渲染）
- U6：日志与可观测性（错误码、请求追踪 ID）
- U7：数据备份与迁移策略
- U8：部署方案（单机 Docker / 云主机 / 家庭 NAS）
- U9：用户注册流程（用户名校验、密码规则、重复账号处理）
